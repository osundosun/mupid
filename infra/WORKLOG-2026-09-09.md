기존 API 헬스체크/롤백과 프런트 홈/배포 SHA 검사는 이미 있어 중복 스모크 테스트를 추가하지 않았다. CI job과 애플리케이션 코드는 변경하지 않았다.

## 로컬 검증 결과

- Docker Compose CLI v5.3.1로 테스트 3개 통과: 정상 변수 전달 및 DB/Redis/API 포트 비공개, 필수값 12개 각각 누락/빈 값 거부(24개 하위 사례), 사용자 지정 S3 endpoint 전달.
- 테스트는 더미 환경 파일만 사용하며 개발자의 MUPID/Compose/Docker 환경변수와 Docker 자격 증명 설정을 제외한다. Docker 데몬이나 서버에 접속하지 않는다.
- receive.sh와 resource-report.sh의 bash -n 구문 검사 통과.
- git diff --check 통과. 백엔드 CI 파일 및 build -x test 미변경 확인.
- 새 자원 도구의 실제 Ubuntu 실행, 서버 Compose 버전 호환성, 새 수신 스크립트의 운영 배포/롤백은 아직 검증하지 않았다. 설정 검사 성공은 외부 Gmail/S3 인증·통신 성공을 보장하지 않는다.

실행 방법:

```bash
python -B -m unittest discover -s infra/tests -v

git diff --check
```

## 적용 및 후속 작업

1. 담당자가 SeaweedFS 설정 유지로 확정했다. Gmail/S3/Redis 접두사는 서버 파일 등록 확인 완료. 운영 SeaweedFS 접근 대상 및 실제 인증·통신 검증은 남아 있다. 클라이언트 URL은 아직 등록해야 한다.
2. DEPLOYMENT-CONTRACT.md에 따라 실제 값을 서버 .env에 추가하고 새 Compose/수신 스크립트를 검증·설치한다. 필수값이 준비되지 않은 서버에 새 Compose부터 설치하면 다음 배포가 차단된다.
3. 다음 새 SHA 배포 시 환경 전달과 기존 상태 검사·롤백 경로를 운영에서 확인한다. 같은 SHA 재시도는 설정 갱신 수단이 아니다.
4. 자원 도구를 서버에서 실행해 기준값을 확보한다. JVM/DB 튜닝은 실제 부하 측정 이후 진행한다.
5. 실패 알림 연결, 릴리스 자동 삭제 정책, AI 배포, 무중단 전환은 후속 작업으로 남긴다. 보관 기간이 확정되지 않아 자동 삭제 도구는 이번 범위에 포함하지 않았다.
