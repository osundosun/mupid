# 260828 — 테스트와 리팩터링

## 학습 목표

- 화면 컴포넌트에 섞여 있던 상태 계산 로직을 테스트하기 쉬운 함수로 분리한다.
- 핵심 사용자 동작을 자동 테스트로 검증해 변경 시 발생할 수 있는 오류를 빠르게 확인한다.

## 진행 내용

- Vitest, jsdom, React Testing Library 테스트 환경 구성
- `normalizeQueryRequest`, `validateQueryRequest` 함수로 입력 정규화와 검증 로직 분리
- `createQueryHistoryEntry`, `addQueryHistoryEntry` 함수로 최근 질문 관리 로직 분리
- 폼 검증, 최근 질문 중복 제거와 최대 3개 제한, 응답 시간 포맷 단위 테스트 작성
- 공백 질문 제출과 정상 질문 전달을 확인하는 `QueryForm` 동작 테스트 작성
- 5일차 테스트·리팩터링 내용을 프로젝트 화면과 README에 반영

## 적용한 React·TypeScript 개념

- 상태 변경과 계산 로직을 분리하는 순수 함수 리팩터링
- TypeScript interface를 이용한 검증 오류 구조 정의
- Vitest의 `describe`, `it`, `expect`를 이용한 단위 테스트
- React Testing Library의 역할 기반 요소 조회와 사용자 이벤트 테스트
- 테스트 종료 후 DOM을 정리하는 공통 테스트 설정

## 문제 해결

컴포넌트 테스트를 연속으로 실행할 때 이전 테스트에서 렌더한 DOM이 남아 동일한 버튼이 두 개 조회됐다. 테스트 공통 설정에서 각 테스트가 끝날 때 `cleanup`을 실행하도록 구성해 테스트가 서로 영향을 주지 않도록 수정했다.

## 산출물

- 폼 요청 정규화·검증 유틸리티와 테스트
- 최근 질문 관리 유틸리티와 테스트
- 응답 시간 포맷 테스트
- 입력 폼 사용자 동작 테스트
- `npm run test` 실행 명령과 테스트 환경 설정

## 검증 결과

- `npm run test` 통과
- `npm run lint` 통과
- `npm run build` 통과
- 공백 질문은 제출되지 않고 오류 메시지가 표시되는 것을 확인
- 같은 DB와 질문은 최근 기록에 하나만 남는 것을 확인
- 최근 기록이 최대 3개로 유지되는 것을 확인
