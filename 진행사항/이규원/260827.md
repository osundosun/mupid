# 260827 — FoodGraph 기획 및 결과 화면 사용자 기능

## 프로젝트 아이디어 기획

### FoodGraph — 개인 맞춤형 식품 관계 탐색 서비스

- **문제 정의:** 기존 서비스는 제품 하나의 영양정보나 점수를 보여주는 데 집중되어 있어 사용자가 저장한 여러 식품에서 반복되는 영양·성분 패턴을 파악하기 어렵다.
- **서비스 목표:** 식품에 단순 점수를 매기지 않고 제품·영양소·원재료·안전정보의 관계를 연결해 사용자가 자신의 식품 선택 패턴을 탐색하도록 돕는다.
- **주요 사용자 흐름:** 제품 검색 → 개인 보관함 저장 → 영양·안전 데이터 연결 → 개인 식품 그래프 생성 → 반복 패턴 및 유사 제품 탐색 → 제품 비교

### 핵심 기능

- 저장한 제품을 영양성분·원재료·검사 부적합 및 회수정보와 연결하는 개인 식품 그래프
- 당류·나트륨·카페인·단백질 등 반복적으로 선택한 영양 패턴 분석
- 최대 3개 제품의 1회 제공량, 100g·mL, 제품 전체 기준 영양성분 비교
- 영양 벡터와 성분 정보를 이용한 유사 제품 탐색 및 유사한 이유 설명
- 품목제조보고번호와 제조사를 우선 활용한 안전정보 연결 및 원문 확인

### 데이터와 분산 처리 설계

- 약 30만 건의 가공식품 영양 DB를 중심으로 원재료, 검사 부적합, 회수·판매중지 데이터를 단계적으로 결합
- MinIO에 원본과 정제 데이터를 저장하고 Spark에서 스키마 정규화·중복 제거·제품 매핑·영양 벡터 생성을 수행하는 배치 구조 검토
- 전체 제품을 직접 비교하는 방식 대신 LSH로 유사 후보를 추출하고 제품별 Top-K 관계 간선을 생성하는 방향 설계
- 검색·보관함·개인 그래프 조회는 Spring과 PostgreSQL에서 처리하고, 전체 관계 계산만 Spark 배치 영역으로 분리

### 범위 결정 기준

- 1주 차에 실제 데이터 건수와 용량, 결측률, 중복 제거 후 고유 제품 수, 제조사·품목번호 매핑률을 측정한다.
- 단일 처리와 Spark 처리시간을 비교해 분산 처리 효과가 확인되는 범위만 최종 MVP에 포함한다.
- 원재료 확보율이나 안전정보 매핑률이 낮으면 영양 패턴과 제품 관계 그래프를 중심 기능으로 유지한다.

## 학습 목표

- 생성된 SQL을 복사해 다른 도구에서 활용할 수 있게 한다.
- 최근 성공 질문을 React 상태로 관리하고 같은 요청을 다시 실행한다.

## 진행 내용

- Clipboard API를 이용한 생성 SQL 복사 기능 구현
- 복사 성공·실패 상태를 사용자에게 안내
- `QueryHistoryEntry` 타입과 `useQueryHistory` 커스텀 훅 작성
- 최근 성공 질문을 최대 3개까지 최신순으로 관리
- 같은 DB와 질문의 중복 기록 제거
- 저장된 질문을 다시 실행하는 버튼 구현
- 모바일에서 결과 버튼과 기록 카드가 한 열로 배치되도록 구성

## 동작 흐름

```text
Text-to-SQL 성공 응답
        ├─ SQL 복사
        └─ 최근 질문에 추가
                 └─ 같은 질문 다시 실행
```

## 적용한 React·TypeScript 개념

- `QueryHistoryEntry` interface로 최근 질문 데이터 구조 정의
- `useState`로 현재 화면의 질문 기록 관리
- `useCallback`으로 기록 추가 함수의 참조 유지
- Props 콜백으로 최근 질문 컴포넌트와 요청 훅 연결
- `navigator.clipboard.writeText`를 이용한 비동기 복사 처리

## 문제 해결

같은 질문을 다시 실행할 때 동일한 기록이 계속 추가되는 문제가 있었다. DB와 질문이 모두 같은 기존 항목을 먼저 제외한 뒤 새 기록을 배열 앞에 추가하고, `slice(0, 3)`으로 최근 3개만 유지했다.

## 산출물

- `useQueryHistory` 최근 질문 상태 관리 훅
