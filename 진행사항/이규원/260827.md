# 260827 — 결과 활용 UI와 최근 질의 기록

## 학습 목표

- 생성된 SQL과 결과 데이터를 사용자가 다시 활용할 수 있는 기능을 구현한다.
- 브라우저 저장소에 최근 성공 질의를 보관하고 상태와 동기화한다.
- 결과 도구와 최근 기록 UI를 재사용 가능한 컴포넌트로 분리한다.

## 진행 내용

- Clipboard API를 이용한 생성 SQL 복사 기능 구현
- 결과 행을 CSV 문자열로 변환하고 Blob 파일로 저장하는 기능 구현
- CSV 값의 쉼표, 큰따옴표와 `null`을 안전하게 처리
- `QueryHistoryEntry` 타입과 `useQueryHistory` 커스텀 훅 작성
- 최근 성공 질의를 localStorage에 최대 5개까지 저장
- 같은 DB와 질문의 중복 기록을 제거하고 최신 기록을 위로 정렬
- 저장된 질문 재실행, 개별 삭제와 전체 삭제 기능 구현
- localStorage의 잘못된 데이터를 걸러내는 타입 가드 작성
- 모바일에서 결과 버튼과 기록 카드가 한 열로 배치되도록 반응형 UI 구성

## 결과 활용 흐름

```text
Text-to-SQL 성공 응답
        ├─ SQL 복사
        ├─ 결과 CSV 저장
        └─ 최근 질의 저장
                 ├─ 같은 질문 재실행
                 ├─ 개별 기록 삭제
                 └─ 전체 기록 삭제
```

## 적용한 React·TypeScript 개념

- `QueryHistoryEntry` interface로 저장 데이터 구조 정의
- `useState` 함수 초기화로 localStorage 최초 기록 읽기
- `useEffect`로 React 상태와 localStorage 동기화
- `useCallback`으로 기록 추가·삭제·초기화 함수 참조 유지
- 타입 가드로 JSON 파싱 결과를 `QueryHistoryEntry[]`로 검증
- Props 콜백으로 기록 컴포넌트와 비동기 요청 훅 연결

## 문제 해결

localStorage의 값은 사용자가 직접 수정하거나 이전 버전의 구조가 남을 수 있어 JSON 파싱만으로 신뢰할 수 없었다. 배열 여부와 필수 필드를 확인하는 `isHistoryEntry` 타입 가드를 작성하고 유효한 항목만 최대 5개까지 복원하도록 처리했다.

CSV 값에는 쉼표나 큰따옴표가 포함될 수 있으므로 모든 셀을 큰따옴표로 감싸고 내부 큰따옴표를 두 번 작성하도록 변환했다. 한글이 깨지지 않도록 UTF-8 BOM도 추가했다.

## 산출물

- `ResultActions` SQL 복사·CSV 저장 컴포넌트
- `useQueryHistory` localStorage 동기화 훅
- `QueryHistory` 최근 질의 목록 컴포넌트
- 최근 질문 재실행·개별 삭제·전체 삭제 UI
- 데스크톱과 모바일 결과 활용 레이아웃
