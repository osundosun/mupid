# 260826 — 비동기 API와 요청 상태

## 학습 목표

- Text-to-SQL 요청을 `Promise` 기반 비동기 흐름으로 전환한다.
- 로딩·성공·실패·취소 상태를 타입과 화면으로 관리한다.
- 중복 요청, 늦게 도착한 응답과 컴포넌트 해제 시 정리 방법을 학습한다.

## 진행 내용

- 동기 Mock 함수를 비동기 `requestQuery`로 전환
- `RequestStatus`의 `idle`, `loading`, `success`, `error` 상태 연결
- `AbortController`와 `AbortSignal`을 이용한 요청 취소 구현
- `QueryErrorCode` union과 `QueryRequestError`로 실패 원인 구분
- `unknown` 예외를 `toQueryError`로 정규화
- `useQueryRequest` 커스텀 훅으로 상태·취소·재시도 로직 분리
- 진행 중 중복 요청 방지와 요청 ID를 이용한 오래된 응답 무시
- `useEffect` cleanup에서 진행 중 요청 정리

## 요청 상태 전이

```text
idle ──제출──> loading ──성공──> success
                 │
                 ├──실패──> error ──재시도──> loading
                 └──취소──> idle (직전 결과 유지)
```

## 실패 원인별 처리

| 오류 코드 | 발생 상황 | 재시도 |
|---|---|---|
| `network` | 서버에 연결하지 못한 경우 | 가능 |
| `timeout` | 응답 시간이 초과된 경우 | 가능 |
| `server` | SQL 생성 중 서버 오류가 발생한 경우 | 가능 |
| `canceled` | 사용자가 요청을 취소한 경우 | 해당 없음 |

## 문제 해결

취소된 요청이나 이전 요청의 응답이 늦게 도착하면 최신 화면을 덮어쓸 수 있었다. 요청마다 ID를 부여하고 현재 ID와 일치하는 응답만 반영했으며, 언마운트 시 `AbortController`를 정리하도록 구현했다.
