# 260825 — React 입력 폼

## 프로젝트 아이디어 기획

### 밥상레이더 — 농작물 가격 원인 분석과 예산 식단 추천

- 농작물별 최근 가격과 평년 가격을 비교하고, 기후·재해·뉴스 데이터를 연결해 가격 변화의 가능한 원인을 함께 보여주는 방향으로 구체화했다.
- 사용자가 인원·예산·끼니 수를 입력하면 현재 가격을 반영한 식단 비용을 계산하고, 예산을 초과할 경우 대체 식재료와 메뉴를 제안하도록 사용자 흐름을 설계했다.
- 단순히 “배추 가격이 올랐다”는 정보를 제공하는 대신 `가격 변화 → 식단 비용 변화 → 대체 메뉴 선택`으로 사용자의 행동까지 연결하도록 범위를 조정했다.

### 필지큐 제주 — 농업재해 현장점검 우선순위 추천

- **문제 정의:** 재해 발생 후 모든 농경지를 동시에 점검하기 어려워 실제 피해 가능성이 높은 필지를 먼저 찾아야 한다.
- **활용 데이터:** 위성영상, 강수·풍속 등 기상자료, 과거 농업재해 이력, 필지 경계와 작물 정보
- **핵심 기능:** 필지별 이상 신호 계산, 재해 노출 정도 분석, 현장점검 우선순위 지도 제공
- **분산 처리 후보:** 다시점 위성영상의 타일 전처리와 필지 단위 공간 조인, 시계열 변화량 계산

### 데이터 현실성 검토

- 공개 API와 다운로드 파일의 제공 범위·갱신 주기·필수 컬럼·조인 키를 조사했다.
- 실제 행 수와 용량, 결측률, 데이터 간 매핑률을 직접 측정하기 전에는 빅데이터 규모를 확정하지 않기로 했다.
- 데이터 의미, 확보 용이성, 분산 처리 전후 차이, 문제 정의, 사용자 체감, 구현 기간을 Go/No-Go 기준으로 정리했다.

## 학습 목표

- Skeleton-2의 `db_id`, `question` 구조를 입력 폼에 연결한다.
- Controlled Component 방식으로 폼 상태를 관리한다.

## 진행 내용

- 명세서와 Skeleton-2 요청 필드 확인
- 데이터베이스 선택과 자연어 질문 입력 UI 구현
- `useState<QueryRequest>`로 입력값 관리
- Select, Textarea, Form 이벤트에 TypeScript 타입 적용
- 빈 질문 검증 후 Mock 결과 화면과 연결

## 명세서와 프론트엔드 연결

| Skeleton-2 필드 | 프론트엔드 구현 |
|---|---|
| `db_id` | Select에서 대상 데이터베이스 선택 |
| `question` | Textarea에서 자연어 질문 입력 |
| `query` | 제출 후 생성 SQL과 결과 표시 |

## 적용한 React·TypeScript 개념

- `useState`를 이용한 입력 상태 관리
- `ChangeEvent`, `FormEvent` 이벤트 타입
- Props 콜백을 이용한 폼 제출
- `aria-invalid`를 이용한 입력 오류 표시

## 문제 해결

공백만 입력한 질문이 제출되지 않도록 `trim()`으로 값을 확인하고, 유효한 질문만 상위 컴포넌트로 전달했다.
