# 260824 — 밥상레이더 기획 및 TypeScript 프로젝트 구조

## 프로젝트 아이디어 기획

### 밥상레이더 — 식자재 공급 충격과 메뉴 원가 위험 분석

- **문제 정의:** 식자재 가격이 갑자기 변해도 외식업자는 여러 가격·기상·뉴스 정보를 직접 확인해야 해 메뉴 원가에 미치는 영향을 빠르게 판단하기 어렵다.
- **주요 사용자:** 소규모 음식점 운영자와 메뉴 원가를 관리하는 실무자
- **활용 데이터:** 농산물 가격·반입량, 기상·재해, 수급 및 관련 뉴스
- **핵심 기능:** 품목별 가격 이상 탐지, 공급 위험 원인 설명, 메뉴별 원가 변동 계산, 대체 식재료 탐색
- **데이터 처리 방향:** 시점과 품목 코드가 다른 데이터를 정규화하고 장기간 가격 시계열과 외부 요인을 연결하는 배치 분석 구조 검토

### 밥상레이더 — 가격 변화에 대응하는 가정식 식단 리밸런싱

- **문제 정의:** 식재료 가격이 급등하면 기존 식단의 장보기 비용이 예산을 초과하지만, 사용자가 영양과 선호도까지 고려해 대체 식단을 다시 짜기 어렵다.
- **주요 사용자:** 주간 식비를 관리하는 1인·다인 가구
- **핵심 기능:** 예산·인원·끼니 수 입력, 예상 장보기 비용 계산, 가격이 오른 재료가 포함된 메뉴 탐지, 대체 메뉴와 장보기 목록 제안
- **기획 결과:** 외식업자용 공급망 분석과 가정용 예산 식단 추천을 비교하고, 데이터 분석 결과가 실제 메뉴 선택 변화로 이어지는지를 핵심 평가 기준으로 정했다.

---

## 학습 목표

- React + TypeScript 프로젝트의 기본 구조를 익힌다.
- Text-to-SQL 요청·응답 데이터에 타입을 적용한다.

## 진행 내용

- Vite React + TypeScript 프로젝트 생성
- API, 컴포넌트, Mock, 타입 폴더 구성
- `type`, `interface`, union type 기초 학습
- 요청·응답 타입과 Mock 데이터 작성
- 생성 SQL과 결과 테이블 출력

## 적용한 TypeScript 개념

- `RequestStatus` union type으로 요청 상태 정의
- `QueryRequest`, `QueryResult` interface 작성
- `Record<string, string | number | null>`로 SQL 결과 행 표현
- `ApiResponse<T>` Generic으로 공통 응답 타입 정의

## 문제 해결

SQL 결과는 질문마다 컬럼이 달라질 수 있어 행을 `Record` 타입으로 정의했다. `columns` 배열을 기준으로 각 셀을 출력해 다른 형태의 결과도 같은 테이블에서 표시하도록 구성했다.
