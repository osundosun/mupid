## 프로젝트 아이디어 기획

### 2026-08-24 — 밥상레이더 서비스 방향 설계

- 식자재 가격·반입량·기상·재해·뉴스를 연결해 공급 충격과 메뉴 원가 위험을 탐지하는 플랫폼 기획
- 농산물 가격이 급등했을 때 가정의 예산과 영양 조건을 유지하도록 식단과 장보기 목록을 다시 구성하는 서비스 기획
- 외식업자 대상 공급망 위험 분석과 가정 사용자 대상 예산 식단 추천을 비교하며 핵심 사용자를 구체화
- 데이터 수집부터 분석 결과 제공까지의 사용자 흐름, 추천 기준, 주요 화면과 데이터 레이크 구조 검토

### 2026-08-25 — 농축산 아이디어 재설계와 데이터 현실성 검토

- 농작물 가격 비교와 기후·뉴스 원인 분석을 결합한 제철 예산 식단 추천 방향으로 밥상레이더 구체화
- 제주 농경지의 위성·기상·재해 데이터를 분석해 현장점검 우선순위를 제안하는 `필지큐 제주` 후보 설계
- 공개 API와 다운로드 데이터의 실제 제공 범위, 갱신 주기, 결측 가능성, 조인 키와 예상 데이터 규모 조사
- 데이터 규모와 분산 처리 필요성이 약하거나 정답 데이터가 부족한 후보를 구분하고 Go/No-Go 검증 항목 작성

### 2026-08-26 — 빅데이터·분산 서비스 후보 확장 및 비교

- `고속도로 정시 도착`, `전기차 충전 성공률`, `도착 시점 주차 성공률`, `환승 성공률`처럼 현재 상태가 아닌 미래의 성공 가능성을 계산하는 아이디어 검토
- 기상 레이더와 침수 이력을 활용한 `폭우 안전 이동 경로`와 `차량 침수 사전 알림` 서비스 검토
- 국내·해외 리콜과 인증정보를 연결하는 `직구제품 안전 레이더`, 실거래·건축물 데이터를 활용하는 `전세 계약 손실 시뮬레이터` 검토
- 전국 음식점 인허가·폐업 이력을 분석하는 `창업 생존위험 진단`과 수년간의 공고·투찰 결과를 활용하는 `나라장터 Bid/No-Bid` 의사결정 서비스 검토
- 교통사고×기상·도로환경, 지하철 혼잡×행사·날씨, 도시민원×도시환경, 폐업×상권조건처럼 서로 다른 데이터의 연결에서 새로운 결과를 만드는 방향 탐색
- 데이터 의미, 규모, 확보 용이성, 분산 처리 전후 차이, 문제 정의, 사용자 행동 변화, 구현 기간을 공통 기준으로 후보 비교
- SSAFY 빅데이터·분산 수상작 사례를 참고해 단순 조회·시각화와 실제 분산 분석이 필요한 서비스의 차이 정리

### 2026-08-27 — FoodGraph 아이디어 구체화

- 여러 식품의 영양성분·원재료·안전정보를 연결해 개인의 반복적인 식품 선택 패턴을 탐색하는 서비스 설계
- 제품 검색, 개인 보관함, 제품 비교, 개인 식품 그래프, 유사 식품의 근거 설명, 검사 부적합 정보 연결 기능 정의
- 약 30만 건의 가공식품 영양 DB와 원재료·회수·검사 정보를 품목제조보고번호와 제조사 기준으로 연결하는 방안 검토
- Spark 기반 데이터 정규화·중복 제거·영양 벡터 생성과 LSH 후보 추출을 이용한 제품별 Top-K 관계 간선 생성 구조 설계
- 실제 데이터 건수·결측률·매핑률과 Spark 적용 전후 처리시간을 먼저 측정한 뒤 최종 MVP 범위를 결정하도록 검증 계획 수립

아이디어를 기능 목록으로만 확정하지 않고, 실제 데이터로 구현 가능한지와 분산 처리가 서비스 결과에 어떤 차이를 만드는지를 함께 검토했습니다.
