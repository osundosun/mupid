- **Essentia Feature 추출, Audio Embedding** 실행 환경 구성 완료

## PostgreSQL, Redis, Monitoring 구성

### PostgreSQL

- EC2 #1(서빙 서버)에 배치, 트랙/사용자/이벤트 원본 데이터 저장 용도로 구축
- 스키마 초안: `tracks`(트랙 메타데이터), `users`, `user_events`(PLAY/SKIP/SEEK/REPLAY/TRACK_LIKE/MOMENT_LIKE 등), `moments`(구간 단위 분석 결과)
- 대규모 청취 이벤트 누적을 고려해 `user_events`는 이후 파티셔닝(날짜/사용자 기준) 적용 여지를 두고 설계

### Redis

- 실시간 랭킹 캐시, 세션, 추천 결과 캐싱 용도로 구축
- Track/Moment 단위 추천 결과를 짧은 TTL로 캐싱해 반복 요청 시 PostgreSQL 부하를 줄이는 구조로 설정

### Monitoring

- 서빙 서버(EC2 #1) 기준 리소스/지표 수집 체계 구축
- 추후 EC2 #2(CPU 워커), GPU Server까지 확장해 파이프라인 전 구간의 처리 시간·리소스 사용량을 비교할 수 있도록 지표 수집 범위 설계

## Essentia Feature 추출, Audio Embedding 환경 구성

- EC2 #2(오디오 CPU 워커) 기준 Essentia 실행 환경 구성 — Decode된 오디오에서 BPM, Energy, Rhythm, Timbre/Spectral Feature 추출 가능하도록 준비
- Track-level 분석뿐 아니라 260826에서 정리한 Moment-level(5초 Window 단위) 분석까지 처리할 수 있는 구조로 환경 구성
- GPU Server 기준 Audio Embedding 생성 환경 구성 — CPU 워커가 적재한 Job을 Consumer로 받아 Batch Inference 처리하는 흐름을 고려해 구성
- CPU 워커 → GPU 워커로 이어지는 Job Producer/Consumer 구조를 실제 환경에서 검증할 수 있는 최소 단위까지 준비
