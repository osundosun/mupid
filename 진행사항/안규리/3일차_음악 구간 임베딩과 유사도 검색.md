# 음악 구간 임베딩과 유사도 검색

**학습 일자** 2026-08-26

## 이 주제를 고른 이유

BPM과 에너지 같은 수치만으로는 악기 구성이나 음색을 충분히 표현하기 어렵다. ACCENCE에서 사용자가 좋아한 순간과 비슷한 구간을 찾으려면 여러 음향 정보를 하나의 벡터로 표현하는 방법이 필요하다.

그래서 오디오 임베딩을 만들고 구간 간 유사도를 계산하는 과정을 알아보았다.

## 오디오 임베딩이란?

오디오 임베딩은 음원의 특징을 일정한 길이의 숫자 배열로 바꾼 것이다. 비슷한 소리를 가진 구간은 벡터 공간에서도 가까워지도록 학습된 모델을 사용한다.

OpenL3는 음원에서 시간별 임베딩과 각 임베딩의 timestamp를 반환한다. 모델의 `content_type`을 `music`으로 지정할 수 있고, 임베딩 크기도 선택할 수 있다.

```python
import openl3
import soundfile as sf

audio, sr = sf.read("track.wav")
embedding, timestamps = openl3.get_audio_embedding(
    audio,
    sr,
    content_type="music",
    embedding_size=512,
    hop_size=0.5
)
```

곡을 처리할 때마다 모델을 새로 불러오면 시간이 낭비된다. 여러 곡을 분석할 때는 모델을 한 번 불러온 뒤 배치 단위로 처리하는 것이 낫다.

## 구간 벡터 만들기

사용자가 1분 42초에 Moment 좋아요를 눌렀다면 그 한 지점만 보면 안 된다. 앞뒤 구간을 함께 봐야 해당 순간까지 이어진 흐름을 알 수 있다.

```text
01:22~01:32  이전 흐름
01:32~01:42  상승 구간
01:42~01:52  선택한 순간
01:52~02:02  이후 전개
```

각 Window의 임베딩을 평균 내고, 에너지와 리듬의 변화량을 붙여 하나의 Moment Vector로 만들 수 있다.

```text
Moment Vector
= Audio Embedding
+ Energy 변화량
+ Rhythm 변화량
+ 앞뒤 구간의 순서 정보
```

단순 평균만 사용하면 구간의 순서가 사라진다. 이전·현재·다음 Window를 정해진 순서로 이어 붙이거나 변화량을 별도 특징으로 저장해야 한다.

## 코사인 유사도

두 벡터의 방향이 얼마나 비슷한지 계산할 때 코사인 유사도를 사용할 수 있다.

```text
cosine_similarity(A, B)
= (A · B) / (|A| × |B|)
```

벡터의 크기보다 특징의 비율을 비교할 때 적합하다. 모든 구간 벡터를 미리 계산해두고, 사용자가 선택한 벡터와 유사도가 높은 상위 K개 구간을 찾는다.

다만 같은 곡의 바로 옆 구간만 계속 나올 수 있으므로 다음 조건을 함께 적용해야 한다.

- 현재 듣고 있는 곡은 결과에서 제외한다.
- 같은 아티스트가 결과를 차지하지 않도록 제한한다.
- 유사도 점수가 너무 낮은 결과는 보여주지 않는다.
- 마지막 순위에서는 장르 다양성과 사용자 선호를 함께 반영한다.

## 저장할 정보

구간마다 아래 정보를 연결해두면 검색 결과를 실제 재생 위치로 바꿀 수 있다.

```text
moment_id
track_id
start_time
end_time
embedding
energy_delta
rhythm_delta
feature_version
```

`feature_version`은 모델이나 Window 설정이 바뀌었을 때 기존 벡터와 새 벡터가 섞이는 문제를 막기 위해 필요하다.

## 프로젝트에 적용한다면

1. Jamendo 음원을 일정한 Window로 나눈다.
2. 각 Window의 임베딩과 음향 특징을 저장한다.
3. Moment 좋아요가 발생하면 앞뒤 Window를 묶는다.
4. 코사인 유사도로 후보 구간을 찾는다.
5. 상위 결과를 직접 들어보고 유사하다고 느껴지는지 확인한다.

초기에는 전체 카탈로그를 순회하는 방식으로 정확성을 확인하고, 검색 시간이 문제가 될 때 벡터 인덱스를 도입하는 순서가 적절하다.
