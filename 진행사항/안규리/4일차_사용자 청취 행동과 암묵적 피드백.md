# 사용자 청취 행동과 암묵적 피드백

**학습 일자** 2026-08-27

## 이 주제를 고른 이유

사용자가 좋아요를 누른 기록만으로 취향을 판단하면 데이터가 부족할 수 있다. 음악을 다시 듣거나 특정 위치로 돌아가는 행동도 선호를 나타낸다. 반대로 추천 곡을 바로 넘긴 행동은 맞지 않는 추천이었다는 신호가 될 수 있다.

ACCENCE의 추천이 사용자의 실제 청취 습관을 반영하려면 이런 행동을 일관된 이벤트로 수집해야 한다.

## 명시적 피드백과 암묵적 피드백

명시적 피드백은 사용자가 의도를 직접 표현한 행동이다.

- Track Like
- Moment Like
- Playlist Add

암묵적 피드백은 행동을 보고 선호를 추정하는 방식이다.

- 곡 끝까지 듣기
- 같은 구간 반복 재생
- 이전 위치로 Seek
- 재생 직후 Skip

암묵적 행동은 상황에 따라 뜻이 달라질 수 있다. Seek Back이 항상 선호를 의미하지 않고, 전화가 와서 곡을 중단했을 수도 있다. 한 번의 행동으로 결론을 내리지 않고 같은 유형의 행동이 반복되는지 함께 봐야 한다.

## 이벤트 구조

이벤트에는 행동 종류뿐 아니라 당시 상황을 다시 확인할 수 있는 값이 필요하다.

```json
{
  "event_id": "evt-001",
  "event_type": "SEEK_BACK",
  "user_id": "user-12",
  "session_id": "session-31",
  "track_id": "track-77",
  "position_ms": 102000,
  "from_position_ms": 118000,
  "occurred_at": "2026-08-27T12:30:10Z",
  "recommendation_id": "rec-204"
}
```

`recommendation_id`를 남기면 어떤 추천 결과에서 발생한 반응인지 추적할 수 있다. `event_id`는 네트워크 재시도로 같은 이벤트가 두 번 저장되는 것을 막는 데 사용한다.

## 행동을 점수로 바꾸기

초기에는 규칙 기반 가중치로 시작할 수 있다.

| 행동 | 해석 예시 |
|---|---|
| Moment Like | 해당 구간에 대한 강한 긍정 |
| Track Like, Playlist Add | 곡 전체에 대한 긍정 |
| Replay, 반복 Seek Back | 구간에 대한 약한 긍정 |
| Play Complete | 곡 전체에 대한 약한 긍정 |
| 재생 초반 Skip | 부정 신호 후보 |
| Pause | 단독으로는 판단하지 않음 |

가중치는 정답이 아니라 초기 가설이다. 예를 들어 5초 안에 Skip한 경우와 곡의 90%를 들은 뒤 Skip한 경우는 다르게 처리해야 한다. 추천 결과가 아닌 사용자의 직접 검색 결과에도 같은 점수를 주면 추천 평가가 왜곡될 수 있다.

## Listening DNA 만들기

각 행동이 발생한 곡 또는 구간의 특징 벡터에 행동 가중치를 곱해 합치면 사용자 선호 벡터를 만들 수 있다.

```text
사용자 선호 벡터
= Σ(구간 특징 벡터 × 행동 가중치)
```

최근 행동에 조금 더 높은 비중을 주면 취향 변화를 반영할 수 있다. 그러나 이벤트가 적은 신규 사용자는 값이 쉽게 흔들리므로 장르 선택이나 인기곡 같은 기본 추천을 함께 사용해야 한다.

## 프로젝트에 적용한다면

1. 프론트엔드와 백엔드에서 같은 이벤트 이름을 사용한다.
2. 이벤트 발생 시간과 실제 재생 위치를 함께 기록한다.
3. 중복 이벤트와 비정상 재생 위치를 정제한다.
4. 규칙 기반 가중치로 첫 Listening DNA를 만든다.
5. 추천 노출부터 클릭, 재생, 완료까지 연결해 결과를 평가한다.

처음에는 가중치를 복잡하게 만들기보다 이벤트가 빠짐없이 수집되는지 확인하는 것이 먼저다.
