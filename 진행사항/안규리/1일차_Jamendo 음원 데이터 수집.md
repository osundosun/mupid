# Jamendo 음원 데이터 수집

**학습 일자** 2026-08-24

## 이 주제를 고른 이유

프로젝트에서 추천과 음원 분석을 하려면 먼저 실제 서비스에 사용할 곡을 확보해야 한다. 기존에 검토한 FMA 데이터셋은 분석 실험에는 쓸 수 있지만, 서비스에서 바로 재생하기에는 제약이 있었다.

Jamendo는 API로 음원과 메타데이터를 제공한다. 다만 API에서 조회되는 곡이라고 해서 모두 같은 조건으로 다운로드하거나 사용할 수 있는 것은 아니다. 그래서 수집 단계에서 음원 정보와 라이선스를 함께 관리하는 방법을 알아보았다.

## Jamendo API에서 확인할 항목

곡 목록은 `GET /v3.0/tracks`로 조회한다. 요청에는 개발자 계정에서 발급받은 `client_id`가 필요하다. 한 번에 받을 수 있는 결과 수가 제한되어 있으므로 `offset`과 `limit`을 이용해 나누어 수집해야 한다.

프로젝트에 필요한 주요 필드는 다음과 같다.

| 필드 | 용도 |
|---|---|
| `id` | 곡을 구분하는 키 |
| `name`, `artist_id`, `album_id` | 곡 메타데이터 |
| `duration` | 너무 짧거나 긴 곡 제외 |
| `audio` | 스트리밍 주소 |
| `audiodownload_allowed` | 다운로드 허용 여부 확인 |
| `license_ccurl` | 라이선스 종류 기록 |
| `musicinfo` | 장르, 악기, 보컬 여부 확인 |

`include=licenses+musicinfo`를 사용하면 라이선스와 음악 정보를 응답에 포함할 수 있다. `vocalinstrumental`, `tags`, `featured` 같은 조건으로 수집 대상을 좁힐 수도 있다.

## 수집 기준 정하기

많은 곡을 받는 것보다 추천에 사용할 수 있는 카탈로그를 만드는 것이 중요하다. 이번 프로젝트에서는 다음 기준을 적용할 수 있다.

- 장르별 곡 수가 한쪽으로 치우치지 않게 한다.
- 보컬곡과 연주곡을 모두 포함한다.
- 한 아티스트나 앨범의 비중을 제한한다.
- 스트리밍 주소가 없거나 분석할 수 없는 곡은 제외한다.
- 라이선스 주소와 다운로드 허용 여부를 반드시 저장한다.

API 응답 원본도 별도로 보관하는 편이 좋다. 나중에 수집 기준이 바뀌었을 때 API를 다시 호출하지 않고 필터 조건만 적용할 수 있기 때문이다.

## 저장 구조

수집 결과는 아래처럼 음원 정보와 수집 상태를 함께 저장한다.

```json
{
  "track_id": "1848357",
  "track_name": "example",
  "artist_id": "421168",
  "duration": 272,
  "audio_url": "Jamendo 스트리밍 주소",
  "download_allowed": true,
  "license_url": "곡별 라이선스 주소",
  "collected_at": "2026-08-24T10:00:00Z",
  "analysis_status": "PENDING"
}
```

`track_id`를 기준으로 중복을 막고, 분석 성공 여부는 `analysis_status`로 관리한다. 음원 다운로드와 특징 추출이 실패한 경우 재시도할 대상을 찾기 쉬워진다.

## 프로젝트에 적용한다면

1. 장르와 보컬 여부를 나누어 API를 호출한다.
2. 곡과 아티스트 중복을 제거한다.
3. 라이선스와 다운로드 가능 여부를 검사한다.
4. 메타데이터 원본과 정제 결과를 나누어 저장한다.
5. 통과한 곡만 음원 분석 대기열에 넣는다.

수집 코드보다 먼저 카탈로그의 포함 기준과 제외 기준을 정해야 이후 분석 결과도 일정하게 유지할 수 있다.
