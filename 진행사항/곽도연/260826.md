## 배운 것

### useEffect 의존성 배열

```jsx
useEffect(fn)              // 매 렌더마다
useEffect(fn, [])          // 마운트 시 1회
useEffect(fn, [a, b])      // a나 b가 바뀔 때
```

정리 함수(cleanup)는 **다음 effect가 실행되기 직전**과 언마운트 때 호출된다.
구독·타이머·이벤트 리스너는 여기서 반드시 해제해야 한다.

```jsx
useEffect(() => {
  const id = setInterval(tick, 1000)
  return () => clearInterval(id)   // 이게 없으면 타이머가 계속 쌓인다
}, [])
```

### 무한 리렌더 함정

```jsx
// ✗ options는 매 렌더마다 새 객체 → effect가 매번 실행 → setState → 리렌더 → 반복
const options = { limit: 10 }
useEffect(() => { fetchData(options) }, [options])
```

객체·배열·함수를 의존성에 넣으면 참조가 매번 달라진다. 해결책은 셋 중 하나:

1. 의존성을 원시값으로 쪼갠다 (`[limit]`)
2. `useMemo`로 참조를 고정한다
3. 애초에 effect 안에서 객체를 만든다

### useMemo / useCallback

- `useMemo` — 계산 **결과**를 기억
- `useCallback` — 함수 **자체**를 기억 (`useMemo(() => fn, deps)`와 동일)

둘 다 공짜가 아니다. 비교 비용과 메모리를 쓴다. 실제로 쓸 만한 경우는:

- 계산이 무거울 때 (큰 배열 정렬·필터)
- `memo`로 감싼 자식에게 넘기는 props일 때
- 다른 훅의 의존성으로 들어갈 때

그냥 "최적화니까 붙이고 보자"는 오히려 손해다.

### 커스텀 훅

`use`로 시작하는 함수로 로직을 빼면 상태 로직만 재사용할 수 있다. 컴포넌트를
감싸지 않아도 돼서 HOC보다 훨씬 깔끔하다.

```jsx
function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value)
  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delay)
    return () => clearTimeout(id)
  }, [value, delay])
  return debounced
}
```
