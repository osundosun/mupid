## 배운 것

### 렌더링 흐름

상태가 바뀌면 React가 컴포넌트 함수를 **다시 호출**해서 새 JSX를 만들고,
이전 결과와 비교(diff)해서 바뀐 DOM만 갱신한다.

중요한 건 "화면을 직접 고치는" 게 아니라 **"이 상태일 때 화면은 이렇다"를 선언**
한다는 점. 명령형으로 DOM을 만지던 습관을 버려야 한다.

### props vs state

| | props | state |
|---|---|---|
| 소유자 | 부모 | 자기 자신 |
| 변경 | 읽기 전용 | `setState`로 변경 |
| 변경 시 | 부모가 다시 넘겨줌 | 리렌더 발생 |

### 상태는 불변으로 다룬다

```jsx
// ✗ 원본을 직접 수정 — 리렌더가 안 일어남
todos.push(newTodo)
setTodos(todos)

// ○ 새 배열을 만든다
setTodos([...todos, newTodo])
```

React는 이전 값과 새 값을 `Object.is`로 비교한다. 같은 참조면 "안 바뀌었다"고
판단해서 리렌더를 건너뛴다.

### key

리스트의 각 항목에 안정적인 고유값을 줘야 한다. 배열 인덱스를 key로 쓰면 중간에
항목을 삽입·삭제할 때 React가 엉뚱한 항목을 재사용해서 입력값이 섞인다.
