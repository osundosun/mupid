## 배운 것

### 이슈 관리

- **Epic → Story → Task** 계층으로 쪼갠다
- 이슈 하나는 "담당자 1명, 하루 안에 끝나는 크기"가 관리하기 편하다
- 브랜치명·커밋 메시지에 이슈 번호를 넣으면 나중에 추적이 쉬워진다

### KPT 회고

| | 내용 |
|---|---|
| **Keep** | 잘 되고 있어서 계속할 것 |
| **Problem** | 문제였던 것 |
| **Try** | 다음 스프린트에 시도할 것 |

Problem만 잔뜩 쌓고 Try로 연결하지 않으면 회고가 불평 대회가 된다. Try는
**다음 스프린트에 실제로 실행 가능한 크기**로 적어야 의미가 있다.

### React Router

```jsx
<Routes>
  <Route path="/" element={<Layout />}>
    <Route index element={<Home />} />
    <Route path="items/:id" element={<ItemDetail />} />
    <Route path="*" element={<NotFound />} />
  </Route>
</Routes>
```

- 중첩 라우트 + `<Outlet />`으로 공통 레이아웃을 유지한 채 내용만 교체
- `useParams`로 URL 파라미터, `useSearchParams`로 쿼리스트링을 읽는다
- 필터·정렬 상태를 `useState` 대신 쿼리스트링에 두면 새로고침·공유에도 유지된다

### 서버 상태 vs 클라이언트 상태

| | 클라이언트 상태 | 서버 상태 |
|---|---|---|
| 예 | 모달 열림, 폼 입력값 | 목록 데이터, 사용자 정보 |
| 소유자 | 브라우저 | 서버 |
| 특징 | 항상 최신 | 언제든 낡을 수 있음 |

서버 상태를 `useState` + `useEffect`로 직접 다루면 로딩·에러·캐시·재요청을
전부 손으로 짜게 된다. TanStack Query 같은 도구가 이걸 대신해준다는 걸 알았다.
