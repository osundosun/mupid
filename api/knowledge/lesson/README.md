|---|---|

## 이 팀이 반복해서 확인한 것

- **기술이 아니라 문제에서 시작한다.** 회고에서 두 사람이 같은 말을 했다 — 구현하고 싶은 기술을 먼저 떠올리고, 오버 엔지니어링을 한다. 새 기술을 넣을 땐 [ADR](../decision/README.md) 에 맥락부터 쓴다. 못 쓰겠으면 넣지 않는다.
- **자동화는 조용히 틀린 데이터를 만든다.** 소규모 배치로 먼저 돌리고 결과를 눈으로 본다. 실패보다 조용히 잘못된 데이터가 더 비싸다.
- **되돌리기 어려운 결정은 ADR 로 고정한다.** 아이디어를 재탐색하는 데 시간이 많이 들었다는 회고가 있었다.
- **문서를 계약으로 믿지 않는다.** 실제로 여러 문서가 코드와 어긋나 있었다 → [failure/doc-drift.md](../failure/doc-drift.md)

## 범위

**이 저장소에서 팀으로 일하며 얻은 것만 담는다.** `진행사항/` 의 개인 스터디 기록은 각자 독립적으로 공부한 것이므로 지식 저장소에 반영하지 않는다.
