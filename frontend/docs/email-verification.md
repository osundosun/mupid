# 이메일 링크 수신 페이지

경로: `/email/verify`

쿼리: `action=SIGNUP` 또는 `action=PW_RESET` (대소문자 구분), `code=인증번호`.
코드는 문자열 그대로 처리합니다. 링크 생성 시 URLSearchParams 등으로 URL 인코딩하세요.

예: `/email/verify?action=SIGNUP&code=0K5AOC`

현재 두 링크 모두 화면에 수신 목적만 표시하며, 실제 인증·계정 생성·비밀번호 변경은 하지 않습니다.
누락/중복/알 수 없는 action은 잘못된 링크로 처리합니다. 번호를 저장하거나 화면/콘솔에 출력하지 않습니다.
검색 색인 금지와 no-referrer 메타데이터를 적용했습니다. 쿼리는 최초 서버 요청에 포함되므로 서버/프록시 로그에서도 code를 마스킹해야 합니다.

연결 지점: `lib/email-verification.ts`의 `EmailVerificationService.verify`.

백엔드에서 필요한 명세:
- 인증 확인 API 요청/응답, 만료·사용완료·잘못된 코드 오류 구분
- SIGNUP 인증 후 가입 계속하기 또는 계정 활성화/로그인 중 어느 흐름인지
- PW_RESET 인증 후 발급할 재설정 권한과 비밀번호 변경 API, 비밀번호 규칙
- 재시도/중복 호출 정책, 이메일 스캐너가 링크를 열었을 때 코드가 소비되지 않도록 하는 정책
- 다른 브라우저/기기에서 열 때 상태 복원 방식

성공 화면과 비밀번호 변경 폼은 위 명세 및 실제 서버 검증 연결 후 활성화해야 합니다.
